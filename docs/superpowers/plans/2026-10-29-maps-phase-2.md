# Maps phase 2: build plan

Spec: `docs/superpowers/specs/2026-10-29-maps-phase-2-design.md`. Each task ends with its tests passing on chromium
and mobile-chrome locally, then CI covers the other four projects.

## 1. Database: grid shape and default

- `db/migrations/021_map_grid.sql`: `ALTER TABLE maps ADD COLUMN grid_type …, ADD COLUMN grid_shown …`.
- `db/schema.sql`: the same columns on `maps`.
- `api/upgrade.php`: step `['021_map_grid.sql', maps exists and has no grid_type, 'Maps can now show a square or hex grid.']`.
- `api/maps.php`: `has_map_grid()`; `map_out` adds `grid_type`, `grid_shown`; `map_save` accepts them (checked
  against the three shapes) when the columns exist.
- Tests: `tests/browser/maps.spec.js` (API) saves and reads back the shape and default, rejects an unknown shape.

## 2. Grid geometry (`static/mapgeo.js`)

- `gridCells(type, size, offset, width, height)` → the SVG pattern's tile (width, height, path) for squares and both
  hex orientations; `squaresAlong(px, size)`.
- Tests: `tests/unit` (Node) for the tile sizes and the square count.

## 3. The overlay and the scale dialog (`static/maps.js`, `static/style.css`)

- Shape select and *Show the grid to everyone* in the *Grid squares* way.
- `L.svgOverlay` with the pattern over the picture's bounds, below pins and routes; *Grid* toolbar toggle,
  remembered in localStorage per map (wrapped in try/catch).
- Measure shows "· N squares" (or hexes) when the map has a grid.
- Tests: browser test that the toggle shows and hides the overlay and the measure text has the square count.

## 4. VTT reading (`static/vtt.js`, Node-testable)

- `readZip(bytes)` (central directory, stored and deflate-raw entries) and `parseVtt(files)` returning
  `{ name, picture: {bytes, type, name}, grid: {type, px, offset_x, offset_y}, scale: {per_square, unit} | null,
  notes: [{x, y, label}], dropped: {walls, lights} , choices? }` for Universal VTT, Foundry scene JSON (+ picture),
  MapTool `.rpmap` and Fantasy Grounds `.mod` (with a list to pick from when there are several maps).
- Tests: unit tests with small fixture files built in the test (a 2×1 PNG in each format).

## 5. Import in the page

- *Import a VTT file…* on the new-map form: read, pick (for a `.mod` with several maps), upload the picture with the
  existing upload helper, `map_save` with grid and scale, `pin_save` for each note (GM only), then open the scale
  dialog with the grid filled in. Errors from `parseVtt` shown in the form.
- Tests: browser tests importing a `.dd2vtt` and a Foundry JSON + PNG, checking grid, scale and pins.

## 6. Export

- *Export…* menu: Picture (download the image URL) and Universal VTT (fetch the picture, base64 it, build the JSON
  with `MapGeo`/`vtt.js` `toUvtt()`); disabled with the hint when there is no grid.
- Tests: unit test of `toUvtt()`; browser test that the download is a valid `.dd2vtt` with the map's grid.

## 7. Plan this trip

- `maps.js`: *Plan this trip* beside *Save route…* and on each saved route; builds the travel address.
- `app.js` travel view: reads `route` or `map`+`path`, fills distance (and mode/unit for space maps), From/To from
  the nearest pins (`MapGeo.nearestPin`), shows the "Planning the trip along…" line with *Reverse*; Depart moves the
  marker to the route's end instead of the To pin.
- Tests: browser test from a saved route through Depart, checking distance, From/To and the marker's new place.

## 8. Docs and wrap-up

- About page: nothing new (no new sources or libraries). Help text on the Maps tab for import and export.
- Copy the spec and plan to the project files folder.
