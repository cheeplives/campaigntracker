# Maps Tab (Phase 1) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Maps tab under World where a GM uploads and scales a map, everyone zooms, pans and measures on it, pins
link it to Encyclopedia entries and Events (players add public note pins), and party groups' markers move when Depart
runs.

**Architecture:** Four new tables (migration 019) and their actions in a new `api/maps.php`, called from
`api/index.php`'s switch the way `api/scabard.php` is. The map picture is an ordinary attachments row with parent type
`map`. The browser gets two new plain scripts: `static/mapgeo.js` (scale, distance, file-name hints, pin matching; no
page needed, so it runs under Node in the tests, like `sessions.js`) and `static/maps.js` (the tab, drawn with Leaflet
1.9.4 in `CRS.Simple`, handed a context object from `app.js` like `fanwikis.js`). `app.js` gains the tab, the route,
the Travel tab's party card and Depart changes, and the links back.

**Tech Stack:** PHP 8 + MySQL, plain JavaScript (no build step), Leaflet 1.9.4 (BSD 2-Clause, vendored), Playwright.

**Spec:** `docs/superpowers/specs/2026-10-28-maps-phase-1-design.md`

## Global Constraints

- Migration file `db/migrations/019_maps.sql`; the same four tables in `db/schema.sql`; install.php runs 019 when
  `SHOW TABLES LIKE 'maps'` is empty. Every maps action fails with `needs_upgrade` (409) before then, and the tab says
  so, as the Library does.
- Coordinates are picture pixels: x right, y down from the top left, as DOUBLE. In Leaflet, `latLng = [-y, x]` and the
  picture's bounds are `[[-height, 0], [0, width]]`.
- Scale units are exactly `'ft'`, `'m'`, `'mi'`, `'km'`. Distances are shown in `unitSystem()` (imperial: ft below
  5280 ft, else mi; metric: m below 1000 m, else km), one decimal place above 10 units' worth only when under 100.
- Only GMs change maps, routes, party groups, scale and markers. Players create pins of kind `note` only, never GM
  only, and change or delete only their own.
- A GM-only map, a GM-only pin or route, a pin on a GM-only entry or a secret event: never in a player's response.
- No new CSP sources. Leaflet is loaded from `static/vendor/leaflet/leaflet.js` and `leaflet.css`; markers are
  `L.divIcon`s, so Leaflet's marker images are not needed.
- GM changes call `touch_campaign($cid)` so open pages see the change notice; players' pins don't, as with notes.
- About page: `E.SOURCES.leaflet = { title: 'Leaflet 1.9.4 map viewer (static/vendor/leaflet)', by: 'Volodymyr
  Agafonkin and the Leaflet contributors', licence: 'BSD 2-Clause', url: 'https://github.com/Leaflet/Leaflet' }`,
  listed under Software and fonts as "The map viewer on the Maps tab: <cite>."
- Database change notice for the PR: "Database change: `db/migrations/019_maps.sql` adds `maps`, `map_pins`,
  `map_routes` and `party_groups`. After deploying, open install.php and press Install or upgrade."

## Review Focus

- **A very large picture on a phone** (an 8000 × 6000 PNG on an iPhone): it must still open and pan. Phase 1 doesn't
  tile; if it fails on `mobile-safari`, the follow-up is browser-side tiling, not a silent blank map. Pinned by a test
  in Task 6 that opens a 6000 × 4000 PNG on every project and checks the image loaded (`naturalWidth > 0`).
- **A player guessing ids:** `map`, `map_pins` and `pin_save` with a GM-only map's id, or `pin_save` with `id` of
  someone else's pin, must answer 404 / 403 and leak nothing. Tested in Tasks 3 and 4.
- **An entry or event deleted, or made secret, after it was pinned:** the pin goes with it (FK cascade), and while it
  is secret players don't get the pin. Tested in Task 4.
- **Depart for a side group:** must not change the campaign's current region or relabel the main group's shifts.
  Tested in Task 8.
- **A map with no scale, or a two-point scale with both clicks on one spot:** measuring says "Set the scale to
  measure"; the dialog refuses a zero distance ("Pick two different places"). Tested in Tasks 2 and 6.
